## P0 — Security holes and deploy blockers

- [ ] **[Handlers] Key the login rate limit on the real client behind a proxy.** `/auth/login` and `/auth/callback` are limited per `RealIP`, which is the socket address without an `IPExtractor`: behind a reverse proxy every client shares one 5 req/s bucket. Configure `e.IPExtractor` for trusted proxies and document it (there is no deployment guide yet).
- [ ] **[Database] Ship the migrations with the server.** Nothing embeds `db/migrations` and `main.go` never migrates; only `scripts/dev.sh` runs the goose CLI, so a production deploy has no supported way to create or upgrade the schema. Embed the directory and run (or expose a command to run) goose Up at startup.
- [ ] **[Database] Document the Postgres 18 minimum.** `uuidv7()` and `VIRTUAL` generated columns need PG 18 and `JSON_EXISTS` needs PG 17. Only `compose.yaml` and the test harness pin `postgres:18`; the README says nothing, the config accepts any DSN, and an older server fails at migration time with an obscure error.

## P1 — Correctness bugs

- [ ] **[Config] Trim OIDC scopes from comma-separated env.** `StringToSliceHookFunc(",")` keeps surrounding spaces, so `GOFF_MGMT_OIDC_SCOPES="openid, email"` sends `" email"` to the IdP, and `"profile, openid"` fails the `openid` check in `Validate()`. Admin emails are already trimmed in `NewAuthService`; trimming in the loader hook covers every list.
- [ ] **[Auth] Decide on session revocation.** Logout only clears the cookie: a copied JWT stays valid until `exp` (a deleted user is rejected on the next request, and roles are re-read from the DB). Document it, or add a revocation list or short-lived sessions with refresh.
- [ ] **[Handlers] Test cross-tenant handler calls.** Company `UpdateMember`/`RemoveMember` with a uid from another company are untested at handler and route level; `AddMember` with another company's user and a duplicate name on `CreateTeam` (409) are only covered by service tests. Each should answer 404 (409 for the duplicate) and leave the other tenant's user unchanged. Malformed uids are already covered (404, `api/routes_test.go`).
- [ ] **[Services] Let a flagset update clear its JSON settings.** `null` for `evaluationContextEnrichment` or `defaultTestingEvaluationContext` passes validation but the repo's `COALESCE` keeps the old value, so the client gets 200 and nothing changes. Tell an absent key from an explicit `null` (a small `Nullable[T]` wrapper with `UnmarshalJSON`), or reject `null` on update.
- [ ] **[Flags] Key flag owners by user id.** `ListByTeam`'s `Owner` filter and `ListTeamOwners` use `users.name`, which isn't unique and defaults to `''`: two users named "Alice" collapse into one owner, and a user with an empty name shows up as owner `""` instead of unassigned. Filter on `fv.created_by` and return `{id, name}` pairs.
- [ ] **[Config] Document that durations need a unit.** `shutdownTimeout: 30` in YAML means 30 nanoseconds, not 30 seconds, because mapstructure assigns a bare number straight onto `time.Duration`; `Validate()` only rejects `<= 0`. Spell the units out in the config reference, or reject sub-millisecond durations in `Validate()`.
- [ ] **[Repository] Narrow `isNoRows`.** It also maps pg 22P02 (invalid input) to "not found", which is right for a malformed uuid in `GetByID` but hides a bad cast in the ~20 other queries that reuse it (on `Exec` errors in `SoftDelete`/`SetDisabled`/`softDeleteFlag` only the 22P02 branch can fire). Validate the uuid in the lookups and keep `isNoRows` to `pgx.ErrNoRows`.
- [ ] **[Repository] Return `ErrNotFound` from lookups.** `UserRepo.GetByID`/`GetByEmail`, `CompanyRepo.GetByID`/`First`/`Membership`, `TeamRepo.GetByID`, `FlagsetRepo.GetByID`, `FlagRepo.GetByID`/`GetForUpdate` and `FlagVersionRepo.GetByFlagAndNumber` return `(nil, nil)` when nothing matches, and `TeamRepo.GetRole` returns `("", nil)`, so every caller must nil-check the result.
- [ ] **[Services] Resolve a flag's team in one query for RBAC.** `RequireFlagRole`/`RequireFlagsetRole` call `FlagsetService.Get`, whose `flagsetCols` carries three `COUNT(*)` subqueries, only to read `team_id`: a flag request (including the rate-limited `/evaluate`) makes five queries before the handler. Flag writes and `Evaluate` load the flagset with its counts a second time. Add a repo lookup `SELECT fs.team_id FROM flags f JOIN flagsets fs … WHERE … deleted_at IS NULL` (and a flagset-only one).

## P2 — Hardening and hygiene

- [ ] **[Auth] Harden the auth cookies against sibling subdomains.** With `auth.cookieDomain` set, a sibling subdomain can plant or overwrite the session cookie (cookie tossing). The state cookie is already host-only but a parent-domain cookie with the same name still wins. Host-only deployments could use the `__Host-` prefix (needs `Secure` and no Domain); the state cookie could use it whenever `cookieSecure` is on.
- [ ] **[Auth] Validate `auth.postLoginRedirect`.** It's operator config, so not an open redirect, but `Validate()` should require a path starting with a single `/` or an absolute http(s) URL, so a typo like `//host` doesn't become a protocol-relative redirect (and silently get no CORS origin).
- [ ] **[Auth] Add `Cache-Control: no-store` to the login redirects.** The callback URL carries the one-time code, but `no-store` is only set on `/api/v1`, not on `/auth/login` and `/auth/callback`. `Referrer-Policy: no-referrer` is already global.
- [ ] **[Services] Keep a team admin.** `TeamService.Create` refuses an admin-less team, but `RemoveMember`, `UpdateMember` and `AddMember` (re-adding the last admin with a lower role) can remove or demote the last admin. Company admins still inherit admin, so nobody is locked out; either guard the last explicit admin or drop the "never admin-less" wording.
- [ ] **[Services] Decide whether a company needs an admin at creation.** `CompanyService.Create` (super admin only) creates a company with no admin (in mono mode unassigned users join as members), so it runs admin-less until the super admin adds one, and `ensureNotLastAdmin` has nothing to protect. Onboarding does create the admin. If every company must have one, take an `adminEmail` like teams and create both in one transaction.
- [ ] **[Repository] Don't log every audit failure at ERROR.** `AuditRepo.Record` logs `context.Canceled` (client disconnect) and errors the caller already handles, so a caller that logs too gets duplicates and disconnects look like a broken audit pipeline. Skip `errors.Is(err, context.Canceled)` in the log, like the RBAC middleware does.
- [ ] **[Services] Skip audit entries for no-op writes.** Re-adding a member or `UpdateMember` with the same role (team and company) writes an update entry where before equals after; a rollback to the current version or a `FlagService.Update` with an identical payload writes a new identical version; `SetDisabled` to the current state, and `TeamService.Update`/`CompanyService.Update`/`FlagsetService.Update` with an empty body, bump `updated_at` and write an entry.
- [ ] **[Handlers] Complete the Swagger annotations.** `@Produce json` is missing on every company route, the team GET/DELETE routes, `/auth/me` and the flag/flagset DELETEs. Reads don't list 403/404, bodies don't list 413 (401 is only in the global description), and company `RemoveMember` documents 400 for a malformed id while the route answers 404. Generated clients may not parse those responses.
- [ ] **[Docs] Write `docs/reference/api.md`.** The API description (`main.go`) and `handler/auth.go` point readers to it, but the file doesn't exist.
- [ ] **[Database] Test the migration round-trip and the flag type parity.** Nothing runs Down then Up again. The parity check in `repository/flag_repo_test.go` covers three payload types and looks the payload up by the type SQL returned, so a wrong SQL type still passes; run the `TestInferFlagType` table cases through `flag_versions.flag_type` keyed by flag name (lax jsonpath mode once typed `["a"]` as `string`).
- [ ] **[Repository] Build the test-harness `TRUNCATE` from the schema.** `allTables` in `internal/testutil/postgres.go` is complete today but hard-coded, so a new table without a foreign key to it would keep rows between tests. Build it from `pg_tables` (minus `goose_db_version`). The `harness.terminate` field is assigned but never read: drop it, or call it from a `TestMain` helper for runs with Ryuk disabled.
- [ ] **[Repository] Use a params struct for `UpsertFromOIDC`.** Its four positional strings (email, name, avatarURL, sub) let a swapped email and sub compile. Cover `AvatarURL`, `LastLoginAt` and `UpdatedAt` in the tests while there (they always pass `""` today).
- [ ] **[Repo] Add `CONTRIBUTING.md`.** The checklist in `.github/pull_request_template.md` links to it, so that link is broken today.
